# 尖括号与 JSON 指令格式对照设计

日期：2026-11-26（Asia/Shanghai）

## 目标

用真实 DeepSeek Flash 配对请求检验项目当前尖括号指令相对常规紧凑 JSON 的输出 token 效率与可执行可靠性。实验不评价自然语言质量，不使用人工判定。

## 方法

- 冻结 30 个有唯一预期指令序列的中文请求，覆盖无参数动作、数值参数、台词、立绘五字段和多指令组合。
- 每个请求在独立会话中分别使用尖括号与 JSON 系统提示；奇偶样本交换调用顺序。
- JSON 采用 `{"commands":[{"type":"...",...}]}`，字段名直接对应现有指令语义，不添加解释性冗余。
- 尖括号使用项目当前协议，如 `<teleport:x=0.35,y=0.85><capture>`。
- token 以 API 返回的 completion token usage 为主；原始响应、metadata、解析结果和耗时逐条保存。
- 两侧均经过严格解析并规范化为同一个 `[{kind, params}]` 序列，再与冻结预期逐项精确比较。

## 指标

- 全输出平均 completion tokens，并单列中位数。
- 严格解析率。
- 完整指令序列准确率。
- 正确执行指令数 / completion token，以及每个正确指令的 token 成本。
- 只在两种格式都语义正确的配对上计算平均 token 差、节省率和 10,000 次配对 bootstrap 95% CI。
- 失败不从可靠性分母移除；API/解析失败均计错。

从已冻结的人体理解结果按自动 per-sample 分数选择代表性最好/最差样本，不进行人工挑选。Penn Action 输出 activity/pose 联系图，RAVDESS 输出 emotion 联系图，并附真实标签和模型预测。图片只用于展示既有实验案例，不参与本次协议格式评分。

## 限制

该实验只支持“在当前 DeepSeek Flash、当前动作集合和当前提示下”的结论。token 优势不自动等价于延迟或价格优势；可靠性结果也不能外推到任意模型或任意 JSON schema。
