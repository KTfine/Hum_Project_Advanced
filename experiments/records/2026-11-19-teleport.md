# 合照传送和即时快门

2026-11-19，Asia/Shanghai。基于父提交 `a9fafa9` 后的工作区，本轮修改合照提示词、流式协议、角色控制器与合成器，并更新实时客户端及独立 API 的回归用例。验证环境为 Windows、Python 3.12.5、OpenCV 4.14.0。

## 分块指令与成片

以项目自带的小白龙 PNG 为角色，将 960×540 的静态纯色帧交给实时客户端的摄像头接口。通过 `StreamingCommandParser` 和 `dispatch_model_commands` 分四段重放 `<teleport:x=0.79,y=0.84,scale=0.65><capture>`。固定单调时钟采样第 0、180 和 400 毫秒，分别读取预览、模型 JPEG 和快门实际写出的 PNG。

| 检查项 | 实测结果 |
|---|---|
| 位置和比例 | 第 0 毫秒的状态已是 (0.79, 0.84, 0.65)。旧立绘占第 389–630 列，最终立绘占第 711–836 列。第 0 和 180 毫秒时，旧立绘所在像素均已恢复背景。 |
| 预览显现 | 第 0 和 180 毫秒的预览分别有 12,752 和 7,624 个像素与第 400 毫秒的清晰预览不同。 |
| 快门与模型观察 | 立即保存的 PNG 与第 400 毫秒的预览逐像素一致。第 0 毫秒与第 400 毫秒的模型 JPEG 字节完全一致。 |

初次探针曾要求显现帧中每个有色像素也必须出现在“最终合成色与背景不同”的像素集合中。这项断言在显现中段失败。扫描带会让半透明边缘显色，最终合成色不能作为原始 alpha 轮廓。探针改用彼此分离的起点和落点，直接检查旧位置的背景像素，再将实际快门与特效结束后的整帧比较。

## 提示词与覆盖范围

在实时入口使用默认中文设定、小白龙图库、无摄像头、无实景层，初始脚点为 (0.5, 0.95)。组装出的指导 system 文本 SHA-256 为 `652b4978dadcd04f345e6632486024fbec5847c1e15a77d68886b69a50ec09dd`，包含随帧脚点说明的合照模板为 `f5bfc51242ca1c6fcf6533da2616dc6545a48d64b1a34fb0e0ac25f87adeba47`。

本次使用本地合成输入和模拟的模型输出，外部模型请求为 0 次。真人摄像头下的观看体验和在线模型对传送指令的遵从率尚未测量。
