# 平视自习室的指导与合照实测

2026-11-20，Asia/Shanghai。四段独立会话共发出 19 次 DeepSeek 图文请求，19 次收到 HTTP 200 和完整回复。指导能读懂人物的位置、接受纠正，并在约定条件满足后只提醒一次。合照能切换模式、换位置、调用快门，但模型说出的站位与最终照片有明显差距。

## 输入与运行条件

使用内置 ImageGen，以上一轮生成的平视自习室为底图，生成两张同机位照片。橙衣人物先站左边蓝色书柜旁，再站到右侧玻璃隔断旁。另取左图的半身裁切，检验同一人物在不同景别下的入场效果。没有拍摄或发送真人照片。客户端接收的摄像头帧为 640 × 480。两张图模拟人物换位，只检验换位前后，不测连续运动、帧率或语音效果。[左图](../runtime/interaction-20261120/person-left.png) · [右图](../runtime/interaction-20261120/person-right.png) · [两次生成的完整指令](../runtime/interaction-20261120/image-generation.txt)

本机父提交为 `a9fafa9`，使用带桌椅分割和深度估计的工作区版本。本轮新增实验入口和记录，使用当前生产提示词、图文消息历史、流式解析、动作分发和 PNG 快门。实际服务返回 `deepseek-flash`，服务指纹 `bc19ba97cbe016479903222bb1578db6`，thinking 为 low，最多 4096 个输出 token。实际指导系统提示 SHA-256 为 `59b4493a3b477174bf4377328b33f2c1c728f7ca5f296cbd44f309679c3b0bff`，合照为 `5b49647cd8b3c0eca29346f6d849cc7a16b20b099b2d2530fad0a4eec5c5479b`。

## 指导对话

| 人物要求或状态 | 真实回复与执行 |
|---|---|
| 询问站在什么旁边，希望全身照更自然，先别拍 | 正确识别“带蓝抽屉的木架”，建议靠近半步、手臂搭架；没有拍照。 |
| 纠正为留在原地、不靠家具，只调整一下上半身 | 接受纠正，改为手插袋、另一只手垂下、弯肘、沉肩等。建议能执行，但一次给的动作比用户要的多。 |
| 委托走到玻璃隔断时提醒一次 | 登记反馈。在书柜旁观察返回静默，出现右图后说“看到你到玻璃隔断旁了”，此后不重复。附带的“光线从右侧透进来”不能从图中确认。 |
| 明确要求现在拍 | 实际保存一张 PNG，与玻璃旁那张摄像头帧逐像素相同。 |

共 6 次请求，全部是原生标签。另有 2 次无待办的常规送帧，未触发 API 请求或发言。[逐轮回复与服务元数据](../runtime/interaction-20261120/guidance-20261120-215735-518335/guidance-results.json)

## 合照主会话

依次邀请入镜、要求肩后露脸、让人物换边、召唤跟随、试坐、纠正桌沿、指定书柜位置、要求并排、按快门。8 次真实请求有 7 次完全使用原生标签。并排回合把说话写成 XML，客户端将标签外文字分块适配为发言；这与后续几何或立绘指令是否执行分别计数。人物换位时没有待办，未触发请求或擅自移动。[事件、命令、落点与每轮 PNG 文件名](../runtime/interaction-20261120/co-photo-20261120-215730-174438/manifest.json) · [连续画面对照](../runtime/interaction-20261120/co-photo-20261120-215730-174438/geometry-contact-sheet.jpg)

| 要求 | 对最终画面的检查 |
|---|---|
| 先入镜，再从肩膀旁露出脸 | 回答“好，我来”并成功切换模式，第一张画面里没有小白龙。指定肩后落点后出现，真人确实挡住了部分立绘，但小白龙脸框的 850 个有效像素可见数为 0。 |
| 人走到画面右边，再叫她跟过来 | 等待时小白龙留在左侧。模型发出一次指定落点的传送，两者脚点横向间距从约 352 px 降至 39 px。 |
| 坐下来，再指定坐在近处白桌的前沿 | 第一次成功切坐姿，仍悬在空地上。指定桌沿后移到桌边，坐姿支撑点在 (337, 317)，比桌子前沿低约 19 px，桌面横穿腰腹。两次均未自然落座。 |
| 站起来，到左边书柜旁 | 脚点到了书柜旁的 (96, 456)，仍保持坐姿。 |
| 回到身旁并排站，收到明确指令后拍照 | 等待时没有提前拍。最终两张脸都可见、照片已保存，但角色仍悬坐。从要求起立起，模型连续三回合提交图库中不存在的“微笑＋正站＋站着”完整组合，客户端三次跳过换图。 |

分别在左右两张全身图复核了自动站位。仅用人体遮罩时，原站位函数能找到旁边的脚点，恢复桌椅遮罩后两张图都找不到候选。当前并排入场求解把家具与角色在二维画面的重叠作为障碍，会连可以站到桌子前的候选位置一起排除。

## 两个独立对照

- **半身入场及肩后快门，2 次请求。** 同一张书柜旁照片裁去下半身后，小白龙从人物左肩后探出。脸框 1,271 个有效像素全部可见，人物与角色实心像素重叠处约 96.9% 保留了原人物，真人脸完整。不过小白龙的鞋子仍落在画内的蓝柜背景上，存在悬浮感。[实际快门](../runtime/interaction-20261120/portrait-20261120-215815-490092/portrait-shutter.png)
- **全身跟随、并排快门，3 次请求。** 使用全新会话，没有先坐下。邀请、无口令换位以及单独说“跟过来”后画面均与底图相同。模型这次发出了正确的 `<follow>`，客户端没有找到身边落点。最后的“并排拍”触发显式传送和快门，角色以站姿入画。两人脚底纵坐标只差约 7 px，但小白龙站在右后方，脸仅约 40% 可见。[实际快门](../runtime/interaction-20261120/standing-20261120-220041-675963/standing-shutter.png)

使用原始底图、手描人物轮廓、图库脸框与桌沿参考线独立检查几何指标，并目测最终照片。三张合照快门 PNG 分别与受检画面字节一致。四段对话共保存四张快门照片。本次没有用手工指定的正确姿势或坐标替代模型输出。[全身主会话测量](../runtime/interaction-20261120/co-photo-20261120-215730-174438/geometry-metrics.json) · [半身测量](../runtime/interaction-20261120/portrait-20261120-215815-490092/geometry-metrics.json) · [独立全身测量](../runtime/interaction-20261120/standing-20261120-220041-675963/geometry-metrics.json)

## 复现

在应用根目录运行以下命令。每次建立新的带时间戳记录，真实模型各次输出可能不同。

```powershell
$frames = 'experiments/runtime/interaction-20261120'
python -m experiments.scripts.guidance_interaction $frames
python -m experiments.scripts.co_photo_interaction "$frames/person-left.png" "$frames/person-right.png" $frames
python -m experiments.scripts.co_photo_interaction "$frames/person-left.png" "$frames/person-right.png" $frames --portrait-entry
python -m experiments.scripts.co_photo_interaction "$frames/person-left.png" "$frames/person-right.png" $frames --standing-pair
```
