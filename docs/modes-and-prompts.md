# 模式、提示词与执行流程

当前实现对应 2026-11-07 的双模式基线 `684d582`。此前方案不定义当前行为。模式决定加载哪份提示词和显示哪种画面；它不限制合法角色动作的执行。

实时客户端将键盘输入或麦克风转写的文字连同当前画面发送给 DeepSeek，并在本机处理流式文字与标签。开启麦克风时，客户端将采集到的音频流发送给 AssemblyAI，收到一轮结束事件后才提交该轮转写。独立图文实验工具使用自己的本地消息历史。[实验工具说明](api-experiments.md)

## 提示词如何组装

[提示词模块](../photo_assistant/prompts.py) 保存共用规则和两种模式的模板。[实时客户端](../photo_assistant/client.py) 的 `build_control_prompt` 选择模板并填入会话信息。

| 部分 | 内容 |
|---|---|
| 共用内容 | 角色设定、回复语言，以及说话、静默、切换模式和拍照的标签。每确定一条指令就输出对应标签 |
| 指导模式 | 有画面时留意真人姿势和表情。用户当前的拍摄目标与指示决定是否需要建议及建议内容，审美取舍由用户决定 |
| 合照模式 | 模型作为一起入镜的伙伴，根据对话和构图自行决定说什么、是否动作，以及使用哪张立绘。提示词提供动作标签、可用立绘及当前场景信息 |

客户端把角色名称、设定、回复语言和输入信息填入对应模板。实时合照模板的初始角色状态还包含几何状态、按从后到前排列的实景层 `scene_layers`，以及角色当前所在的层 `layer_index`。修改提示词模块后重新运行客户端即可加载新的模板。

### 合照中的站位、姿势与画面调整

`sit`、`stand`、`follow` 和 `peek` 分别让角色坐下、站好、来到真人身边或从真人身后探身。客户端根据场景确定落点。要移到画面中的指定位置，使用 `teleport` 提供目标脚点的 x、y 坐标。

`brace` 让角色扶住墙或柱子。客户端在当前帧寻找有深度差的竖边、能看见的墙脚及旁边能站的位置，再选相应的手贴墙。扶稳后，随帧的 `wall_contact_xy` 给出掌缘的归一化坐标。`stand` 让角色松手后在原地恢复自然站姿。

`tachie` 选择一张完整立绘。模型可以随对话调整表情或手势。`rotate` 使整个人在画面中倾斜，`layer` 改变整组的遮挡顺序。连续发出多个标签时，客户端依次执行，快门保存执行到 `capture` 时的画面。

实时客户端使用小白龙的透明 PNG 立绘。图片按脸部、手部、手臂、上半身、腿部五项索引。当前库实际可用的组合列在合照提示词末尾。只换表情时，另外四项沿用当前立绘。如果图库有兼容的表情变体，模型可以在两段台词之间插入 `tachie`，也可以保持当前表情。立绘在标签解析后切换，语音按播放队列的进度朗读。

进入合照时，摄像头先显示实景。真人鞋底可见时，客户端优先选用自然正站立绘，寻找紧邻真人的一块地面，让两双鞋在画面中几乎同高且横向错开。真人下半身出框时，角色从躯干或前景障碍物侧边探身。画面中没有可用的真人参照，但能估出桌子后方的地面位置时，角色站在可见面积最大的那张桌子后。找到位置后，脚点和画面大小固定。真人离开原位后，默认肩后侧探会原地转为正站一次。已通过 `tachie` 指定的立绘优先。入场找不到位置时等待下一帧。无相机时在空白背景显示起始立绘。独立图文实验由调用方提供合成画面。

实时合照的提示词说明本次使用的机位。固定机位随图传入的 `scene_objects` 沿用入场时识别的家具位置，移动机位使用最近一次场景分析的结果。同类的多张桌子各占一项，附类别、置信度、归一化边界、横向中心和识别时可见的轮廓下沿。有地面估计时，`behind_y`、`front_y` 分别建议站到该物体后方和前方的脚点纵坐标。模型结合这些位置与最新画面辨认用户所指的桌子。角色入画后，随图信息还包含实际脚点以及直立投影高度占画面高度的比例 `standing_height_ratio`。用户询问遮挡时，角色根据最新合成图说明实际露出的部位。

无参数的 `sit` 优先尝试离摄像头较近的坐面，包括椅子、长椅、沙发、床和桌子的边沿。“找个离镜头远的地方坐”用 `<sit:distance=far>`，从远到近寻找可用支撑点。“坐到远处那张白桌上”指明了物体，模型会结合画面和 `scene_objects` 确定那张桌子，给出物体中心或可坐边沿的坐标。找不到可靠的支撑点时，角色保持原位和姿势。[动作标签](reference/command-protocol.md)

换角色时用 `--sprite-catalog` 指定新立绘库的 JSON 文件。合照模板随库内容更新。[素材库说明](../models/avatars/README.md)

实时合照中，角色入画或动作就位时，客户端在调试日志中记录 `canvas.ready`。用户再次提问时，模型可以根据当前画面和 `pose_settled` 回答。

### 主动看画面

用户第一次提交文字或语音转写后，内置指导和合照模式每 2 秒有一次观察机会。只要会话空闲、摄像头有可用画面，客户端就把最新画面交给模型。人保持同一个姿势时也会送图。会话忙或画面暂缺时跳过本次机会，后面只取届时的最新画面。新的用户输入优先，可以打断观察回复。

指导模式提交真人画面，合照提交实景与立绘的合成图。定时送来的画面带有观察标记。两种内置提示词都要求模型沿用用户最近的要求，拍照和切换模式按用户要求执行，已经完成的请求无需重复。合照时，小白龙可以根据画面避开遮挡、换姿势，也可以用 `<blank>` 保持安静。定时观察和用户对话使用同一套标签解析和执行逻辑。无摄像头或使用自定义 `--prompt` 时，继续按用户输入发送请求。

## 模式切换

1. 启动时选择 `guidance`，准备对应的 system 提示词。用户提交拍摄目标后发起 API 请求。
2. 用户在终端输入切换意图，模型决定是否生成 `<mode:co-photo>` 或 `<mode:guidance>`。
3. 解析器收到完整标签后，记录 `session.mode_requested`，请求切换。
4. 实时客户端收完本轮回复，完整的说话标签照常输出。随后使用对应提示词打开新会话。
5. 新会话就绪后，记录 `session.mode_ready`，更新 ON/OFF 状态并切换画面。接在切换标签后的角色动作和快门在目标视图执行。

客户端不匹配用户话语中的关键词；只说“已经切换”不会触发模式切换。重复请求当前模式不重建会话，失败也不会提前记录为加载成功。

ON/OFF 只表示最后成功加载的提示词：OFF = guidance，ON = co-photo。尚未成功加载时没有已就绪模式。控制台显示 `[mode] loaded: OFF (guidance)` 或 `[mode] loaded: ON (co-photo)`，本地 JSONL 中也记录模式与 `include_character`。

切换时保留摄像头连接，并将最近的用户原话和回复交给新模式。合照客户端负责入场定位。

如果入场持续等待，终端会提示等待摄像头画面或寻找侧探位置。日志的 `canvas.entry` 记录入场进度，`api.input.character_placement` 记录该帧的脚点与倍率。

## 画面与动作

| 模式 | 用户预览与模型图像 | 快门保存的 PNG |
|---|---|---|
| 指导 | 摄像头画面 | 快门时的摄像头原图 |
| 合照 | 按当前脚点、大小和遮挡层合成角色，预览另显示传送效果 | 按快门时的角色图层、目标位置、大小和摄像头帧合成清晰立绘 |

默认使用固定机位。每次进入合照时，客户端用第一张可分析的画面识别家具、地面和背景深度，随后持续分割真人。预览显示最近完成分割的摄像头画面，真人和轮廓来自同一帧。快门按拍摄当下的人物轮廓合成。入场时让需要合照的桌椅尽量露出来；挪动相机或家具后，退出合照再进入即可重新识别。

手持拍摄或持续移动镜头时，用 `--moving-camera`（PowerShell 为 `-MovingCamera`）持续更新场景。这个模式优先显示最新的摄像头画面，快速移动时预览中的遮挡轮廓可能暂时滞后。

客户端取出当前五项标签对应的透明立绘，按图层与摄像头画面合成。没有可用相机帧时使用空白背景。自动侧探入场确定落点时，预览在该处播放约 350 毫秒的扫描光效。后续每条 `teleport` 标签闭合时，脚点和站高倍率一起生效，预览在新位置播放同样的光效。传送后紧接快门时，照片和模型观察图都直接采用目的地的清晰立绘。

侧面探身的位置由同一帧的遮挡轮廓、立绘脸部与身体共同确定。半身入场默认以真人两颊宽度的约 71% 作为角色脸宽，允许鞋底在画外。全身照检查鞋底距离。每次收到 `follow` 时，客户端根据当下取景判断一次。已经在身边就保持，确实需要换位置才播放传送效果。之后真人移动时，角色保留先前落点。

同一地面上，鞋底落点越靠近地平线，角色在画面中就越小。横移可以只改变 x 并沿用当前 y。省略 `scale` 时，传送保留当前大小倍率，实际投影高度随落点变化。实景合成根据新落点和可用的场景深度更新遮挡。

全身照按真人可见的鞋底定深度，默认给两双鞋留出约真人画面身高 2% 的前后差。半身或头肩近景按真人轮廓估计画外脚点，用可见的躯干侧边检查遮挡。随帧的 `person_framing` 记录最近定位时的景别，`placement_source` 记录站位方式，`current_tachie` 是当前画面使用的立绘。

两种模式都执行当前角色支持的合法动作。对于 layer，客户端按当前实景层数校验索引。隐藏角色时收到的合法动作仍会改变保留的角色状态。模型根据用户意图决定是否说话、调整构图或询问目标。

## 流式标签

支持单行连续标签，例如 `<tachie:face=微笑,hand=无动作,arm=自然下垂,torso=半身歪斜向右,legs=站着><speak:来，一起看镜头吧。>`。台词在逗号等停顿处和标签结尾提交朗读；动作标签以 `>` 闭合后解析、分发。标签可以跨网络分块。

标签外普通文字在正常客户端中增量适配为说话，记录 `parser.plain_text_adapted`；不会从这些文字推断动作或模式。判断模型是否原生生成标签，应查看原始输出，不能只看控制台的 speak 结果。未知、非法或不完整标签不猜测执行。语音播放开启时，已解析的台词按句进入朗读队列。

## 自定义与兼容入口

`--prompt` 完整覆盖内置提示词，custom 视图和模型输入同样将角色叠加在镜头画面上。自定义提示词保持原样。旧 photo:enter 标签仅用于解析历史记录。

完整参数见[客户端 CLI](reference/client-cli.md)。流式指令及参数校验见[标签协议](reference/command-protocol.md)。

当前模型效果及限制见 [验证索引](../experiments/records/README.md)。
