# 模式、提示词与执行流程

当前实现对应 2026-11-07 的双模式基线 `684d582`。此前方案不定义当前行为。模式决定加载哪份提示词和显示哪种画面；它不限制合法角色动作的执行。

实时客户端通过 HTTPS 将用户输入的文字和当前画面发送给 DeepSeek，并在本机处理流式文字与标签。文字可来自键盘，也可来自已启用的 Vosk 麦克风听写。独立图文实验工具使用自己的本地消息历史，其模式确认和回调方式见[实验工具说明](api-experiments.md)。

## 提示词如何组装

[提示词模块](../photo_assistant/prompts.py) 保存共用规则和两种模式的模板。[实时客户端](../photo_assistant/client.py) 的 `build_control_prompt` 选择模板并填入会话信息。

| 部分 | 内容 |
|---|---|
| `_IDENTITY`、`_TURNS`、`_OUTPUT` | 角色设定、用户消息和自动观察的处理、快门时机以及标签输出格式 |
| `PHOTO_GUIDANCE_PROMPT` | 共用规则 + 真人拍照指导职责；默认使用，不含模型动作目录、几何状态或动作协议 |
| 合照提示词 | 共用规则、合照互动、立绘库的标签和可用组合、起始立绘和构图指令 |

客户端组装每个会话的角色名称、设定、回复语言、起始上下文和输入渠道。实时合照模板的初始角色状态还包含几何状态、按从后到前排列的实景层 `scene_layers`，以及角色当前所在的层 `layer_index`。修改提示词模块后重新运行客户端即可加载新的模板。

### 合照中的站位、姿势与画面调整

“坐到桌沿”“站起来”“跟我过来”“站到我身后”分别用 `sit`、`stand`、`follow`、`peek`。客户端处理起坐或相对人和桌子的落点。去指定空地、桌前桌后或改变与镜头的距离用 `teleport`。

“你去扶那根柱子”用 `brace`。客户端在当前帧寻找有深度差的竖边、能看见的墙脚及旁边能站的位置，再选相应的手贴墙。若用户只是问自己怎么扶墙摆姿，助手会给真人建议。扶稳后，随帧的 `wall_contact_xy` 给出掌缘的归一化坐标。“松手站好”让角色在原地恢复自然站姿。

用户另外指定表情或手势时，用 `tachie` 选一张与当前站姿、坐姿或探身姿势相容的立绘。用户同时要求站位、摆姿和拍照时，按这个顺序执行。整个人在画面中倾斜用 `rotate`，只有明确要求改动整组遮挡顺序时才用 `layer`。

实时客户端使用小白龙的透明 PNG 立绘。图片按脸部、手部、手臂、上半身、腿部五项索引。当前库实际可用的组合列在合照提示词末尾。只换表情时，另外四项沿用当前立绘。

进入合照时，摄像头先显示实景。真人鞋底可见时，客户端优先选用自然正站立绘，寻找紧邻真人的一块地面，让两双鞋在画面中几乎同高且横向错开。真人下半身出框时，角色从躯干或前景障碍物侧边探身。画面中没有可用的真人参照，但能估出桌子后方的地面位置时，角色站在可见面积最大的那张桌子后。找到位置后，脚点和画面大小固定。真人离开原位后，默认肩后侧探会原地转为正站一次，角色安静等待。用户已指定的立绘优先。被问到姿势时，角色按最新画面和 `current_tachie` 回答。入场找不到位置时等待下一帧。无相机时在空白背景显示起始立绘。独立图文实验由调用方提供合成画面。

实时合照用 `scene_objects` 随图传入本帧识别到的物体。同类的多张桌子各占一项，附类别、置信度、归一化边界、横向中心和可见轮廓下沿。有地面估计时，`behind_y`、`front_y` 分别建议站到该物体后方和前方的脚点纵坐标。模型可结合这些位置与画面判断“靠窗的桌子”指哪一张。角色入画后，随帧信息还包含实际脚点以及直立投影高度占画面高度的比例 `standing_height_ratio`。客户端按脚点和可用的相对深度合成遮挡。

用户只说“坐下”时默认坐近桌前沿，也可以指定远桌或按画面位置选桌。从桌沿起身会回到桌边的地面。自动观察可以完成已委托的快门，角色动作等用户要求。[动作标签](reference/command-protocol.md)

换角色时用 `--sprite-catalog` 指定新立绘库的 JSON 文件。合照模板随库内容更新。[素材库说明](../models/avatars/README.md)

固定机位前的用户可能看不到预览。实时合照中，角色实际入画，或按要求换好位置、摆好姿势后，客户端在终端以角色口吻确认一次。同一个姿势保持期间，角色安静等待。用户再问“你好了吗”时，模型会参考最新画面及当前立绘回答。目前这条确认通过文字显示。

用户在终端输入的文字原样送入对话。询问当前构图时，模型可以给一个具体建议，答完即止。入镜、点头、微笑本身都不触发快门。

指导模式在用户限定站位或只想改一个动作时给一项能当场做到的调整。委托到位提醒时只确认可见的变化，推断光源方向需要画面依据。

用户委托后续任务时，模型在真人回合发出 `<wait:feedback>` 或 `<wait:capture>`。前者用于在调整完成后反馈一次，后者用于在约定条件满足时拍一张。客户端只在有待办时发起带 `【自动观察】` 的请求。条件还没满足时模型返回 `<blank>`。新用户输入优先，重新根据最新要求决定是否继续待办。“等我说拍再拍”会等下一条真人指令。

## 模式切换

1. 启动时选择 `guidance`，准备对应的 system 提示词。用户提交拍摄目标后发起 API 请求。
2. 用户在终端输入切换意图，模型决定是否生成 `<mode:co-photo>` 或 `<mode:guidance>`。
3. 解析器收到完整标签后，记录 `session.mode_requested`，请求切换。
4. 实时客户端收完本轮回复，完整的说话标签照常输出。随后使用对应提示词打开新会话。
5. 新会话就绪后，记录 `session.mode_ready`，更新 ON/OFF 状态并切换画面。接在切换标签后的角色动作和快门在目标视图执行。

客户端不匹配用户话语中的关键词；只说“已经切换”不会触发模式切换。重复请求当前模式不重建会话，失败也不会提前记录为加载成功。

ON/OFF 只表示最后成功加载的提示词：OFF = guidance，ON = co-photo。尚未成功加载时没有已就绪模式。控制台显示 `[mode] loaded: OFF (guidance)` 或 `[mode] loaded: ON (co-photo)`，本地 JSONL 中也记录模式与 `include_character`。

切换时保留摄像头连接，并将最近的用户原话、回复和已登记的待办交给新模式。单纯邀请入镜时，客户端直接完成定位。若用户另有需看新画面才能完成的要求，例如“进来，等我们都入镜再拍”，合照客户端等定位完成后再检查待办。

合照中出现 `<blank>` 表示本轮观察没有新动作。如果入场持续等待，终端会提示等待摄像头画面或寻找侧探位置。日志的 `canvas.entry` 记录入场进度，`api.input.character_placement` 记录该帧的脚点与倍率。

## 画面与动作

| 模式 | 用户预览与模型图像 | 快门保存的 PNG |
|---|---|---|
| 指导 | 摄像头画面 | 快门时的摄像头原图 |
| 合照 | 按当前脚点、大小和遮挡层合成角色，预览另显示传送效果 | 按快门时的角色图层、目标位置、大小和摄像头帧合成清晰立绘 |

客户端取出当前五项标签对应的透明立绘，按图层与摄像头画面合成。没有可用相机帧时使用空白背景。自动侧探入场确定落点时，预览在该处播放约 350 毫秒的扫描光效。后续每条 `teleport` 标签闭合时，脚点和站高倍率一起生效，预览在新位置播放同样的光效。传送后紧接快门时，照片和模型观察图都直接采用目的地的清晰立绘。

侧面探身的位置由同一帧的遮挡轮廓、立绘脸部与身体共同确定。半身入场默认以真人两颊宽度的约 71% 作为角色脸宽，允许鞋底在画外。全身照检查鞋底距离。每次明确要求“跟过来”时，客户端根据当下取景判断一次。已经在身边就保持，确实需要换位置才播放传送效果。之后真人移动时，角色在先前落点等待。

用户明确让小白龙自己靠近或远离镜头，模型才发送带 `depth=near` 或 `depth=far` 的传送。它按画面选一个更近或更远的鞋底落点，通常省略 `scale`。客户端以入场定好的身高为参照，按鞋底落点到地平线的距离计算新位置的投影高度。即使半身取景遮住了地板，也可以沿用上次的地平线估计或近似值来缩放。这时逐像素前后排序取决于当前帧能否提供可靠的地面深度。用户让小白龙回到身边时使用 `<follow>`。普通横移沿用当前脚点高度和景深模式。

全身照按真人可见的鞋底定深度，默认给两双鞋留出约真人画面身高 2% 的前后差。半身或头肩近景按真人轮廓估计画外脚点，用可见的躯干侧边检查遮挡。随帧的 `person_framing` 记录最近定位时的景别，`placement_source` 记录站位方式，`current_tachie` 是当前画面使用的立绘。

两种模式都执行当前角色支持的合法动作。对于 layer，客户端按当前实景层数校验索引。隐藏角色时收到的合法动作仍会改变保留的角色状态。模型根据用户意图决定是否说话、调整构图或询问目标。

## 流式标签

支持单行连续标签，例如 `<tachie:face=微笑,hand=无动作,arm=自然下垂,torso=半身歪斜向右,legs=站着><speak:一起看镜头吧。>`。每个标签以 `>` 闭合后立即解析、分发，标签可以跨网络分块。

标签外普通文字在正常客户端中增量适配为说话，记录 `parser.plain_text_adapted`；不会从这些文字推断动作或模式。判断模型是否原生生成标签，应查看原始输出，不能只看控制台的 speak 结果。未知、非法或不完整标签不猜测执行，TTS 当前关闭。

## 自定义与兼容入口

`--prompt` 完整覆盖内置提示词，custom 视图和模型输入同样将角色叠加在镜头画面上。自定义提示词保持原样。旧 photo:enter 标签仅用于解析历史记录。

完整参数见[客户端 CLI](reference/client-cli.md)。流式指令及参数校验见[标签协议](reference/command-protocol.md)。

当前模型效果及限制见 [验证索引](../experiments/records/README.md)。
