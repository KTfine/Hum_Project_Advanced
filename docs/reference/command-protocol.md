# 模型文本标签协议

标签位于 API 返回的流式文本中。实时客户端从 `<speak:` 开始增量提取台词，在逗号等停顿处分段朗读。角色动作和快门在完整标签闭合并通过参数校验后执行。[解析器](../../photo_assistant/protocol.py)

## 当前标签

| 格式 | 含义与校验 |
|---|---|
| `<speak:内容>` | 显示台词；启用朗读时按停顿分段，闭合标签提交剩余台词 |
| `<blank>` | 无需回应；不带参数 |
| `<capture>` | 无参数。用户要求拍摄时保存一张照片。指导模式拍摄摄像头原图，合照模式拍摄包含角色的合成画面 |
| `<mode:guidance>` / `<mode:co-photo>` | 请求任务切换；同模式请求不重复重建 |
| `<teleport:x=0.35,y=0.85>` | `x`、`y` 指定鞋底在画面中的目标位置，范围均为 -2 到 3。可选的 `scale` 指定角色大小倍率，范围为 0.1 到 3。 |
| `<follow>` | 无参数。根据当前画面判断一次。已在真人身边时保持原位，需要换位时传送到身旁并站定。适用于半身照和全身照 |
| `<peek>` | 从真人肩后探出。全身取景时只后移少许，用横向站位让大半躯干藏在真人身后，同时检查脸部可见度和两双鞋之间的空隙。 |
| `<brace>` 或 `<brace:x=0.55>` | 按当前帧找到可扶的竖直支撑边，从开放的一侧伸手。可选的 x 是目标边在整幅画面中的横坐标（0～1）。成功后随帧提供 `wall_contact_xy`；找不到支撑时保留原位，同一回复里紧随的快门会跳过。 |
| `<sit>` 或 `<sit:distance=near>` | 按摄像头视角由近到远寻找可用坐面，候选包括椅子、长椅、沙发、床和桌子。 |
| `<sit:distance=far>` | 在相同候选中由远到近寻找可用坐面。 |
| `<sit:x=0.50,y=0.60>` | 指定画面中的物体或边沿，例如“右侧那把椅子”或“远处那张白桌”。x、y 是物体中心或可见坐面边沿的归一化坐标，范围均为 0～1。对于未识别类别的物体，客户端用指定处的图像与深度判断能否落座。 |
| `<stand>` | 恢复图库中的自然站姿。起立去书柜旁时先发此标签，再用 teleport 给出地面脚点。 |
| `<rotate:to,value=10,ms=300>` | 绝对角度，value 为 -180–180 |
| `<rotate:by,value=-5,ms=300>` | 相对角度，value 为 -180–180 |
| `<tachie:face=微笑,hand=无动作,arm=自然下垂,torso=半身歪斜向右,legs=站着>` | 按五项标签精确选择一张立绘，整组立即生效 |
| `<layer:to,index=1>` | 立即将角色移到指定层。index 表示角色后方的实景层数，取从 0 到当前实景层数的整数 |

按远近落座时，客户端取各物体轮廓内的相对逆深度中位数排序，数值较大表示更靠近摄像头。客户端按顺序检查各物体的坐面边沿和遮挡，采用第一个能落座的物体。旧写法 `<sit:table=near>` 和 `<sit:table=far>` 分别按 `distance=near` 和 `distance=far` 处理，候选包括所有受支持的坐面。选择具体物体时使用坐标形式。

默认摄像头的 `scene_layers` 为 `["obstacle", "person"]`。同帧识别的桌椅等实例都属于 obstacle 组。自动合成在地面深度可用时，根据角色脚点判断哪些物体像素在角色前方。模型要走到某一张桌子的前后，应根据该桌在 `scene_objects` 中的位置及画面选择落脚点。

显式 `layer` 按整组覆盖遮挡顺序。在上述默认组序下，指定 index=0 把角色置于物体和真人后，index=1 在物体前、真人后，index=2 在两组前。自定义图层顺序以当前 `scene_layers` 为准。启用实景投影时，传送或跟回真人身边会恢复自动遮挡。要在新位置手动指定图层，先发 `teleport` 再发 `layer`。仅使用静态图层时，传送会保留当前图层。两项连续指令 `<layer:to,index=1><capture>` 会按新层次拍照。

切换立绘时，一条 `tachie` 标签必须写齐以下五项，每项出现一次，每次取一个值。客户端将标签解析为一个以字段名为键的字典，在已加载的立绘库中精确查找整组。字段顺序不影响查找。漏项、额外字段、重复字段、未知值或库中缺图均保持当前立绘。

| 字段 | 可选值 |
|---|---|
| face（脸部） | 微笑、龇牙笑、高冷表情、害羞、惊讶、思考、难过、鼓脸小生气 |
| hand（手部） | 比耶、无动作 |
| arm（手臂） | 自然下垂、伸直举高过头、背在身后、左手扶墙、右手扶墙 |
| torso（上半身） | 正着站、半身歪斜向右 |
| legs（腿部） | 站着、坐着、蹲下 |

实时客户端自动处理入场。全身照默认自然正站，选择真人左边或右边的近邻空位，两人鞋底高度接近。半身或头肩照从真人身体或前景障碍物侧边探出，预览在落点播放传送光效。找不到合适位置时等待下一帧。无相机时显示起始立绘。

模型可在同一轮换图和传送。例如 `<tachie:face=微笑,hand=无动作,arm=自然下垂,torso=半身歪斜向右,legs=站着><teleport:x=0.75,y=0.90>` 选用向右探身的立绘，以当前画面的指定脚点换位。只换表情时，完整标签中沿用其余四项。

传送使用整幅画面的归一化坐标，左上角为 (0, 0)，右下角为 (1, 1)。客户端在入场或收到 `<follow>` 时，按当时画面中的真人确定角色大小。落地后保存脚点和投影大小。真人走开时，默认侧探立绘会在原地换为自然正站。已经明确选定的立绘会保留。

让小白龙靠近或远离镜头时，选择相应的地面脚点即可。客户端按落点和地平线估计角色的投影高度。比如在平地上移到画面下方，鞋底离地平线更远，角色会显得更大。静态图层也可根据入场时确定的身高和估计地平线计算大小。想让她回到真人身边时使用 `<follow>`。

用户说“跟过来”时用 `<follow>`。坐姿起立后并排拍全身照用 `<stand><follow><capture>`。指定地面坐标时使用 `teleport`。半身合照横移后拍摄的示例为 `<teleport:x=0.5,y=1.8><capture>`。快门和模型图像都使用目的地的清晰立绘。

所有数值均须有限。未知参数、重复参数、缺少必需参数或数值超限都会使整条指令失效。`ms` 仅适用于旋转，默认为 350，范围为 0 到 3000 的整数。相对旋转基于上次的目标角度累加，最终角度限制在 -180 到 180 度。换图时保留构图位置。

## 流式与适配

例如 `<speak:看镜头，放松肩膀。><teleport:x=0.7,y=0.9>` 可单行连续输出。即使网络暂时只送达 `<speak:看镜头，`，首段台词也能进入合成队列。后续传送指令要等闭合并验证坐标后执行。

用户明确要求拍下当前画面时，模型可输出 `<capture>`。实时客户端读取指令执行时最新的摄像头帧，合照模式按当前姿势、表情和遮挡关系合成照片。照片按摄像头分辨率写为无损 PNG，保存在项目的 `photos/` 目录中。没有可用相机帧时跳过该次拍摄。

摄像头持续更新预览。每次键盘提交或语音转写完成时，实时客户端优先将用户的话和当时可用的画面发给模型。用户开始对话后，内置模式每 2 秒有一次发送最新摄像头画面的机会，静止画面也参与。会话忙时跳过本次观察。观察回复接受 `speak` 和 `blank`，在已加载的合照视图中还可以用 `tachie` 原地换脸，保持其余四项姿势。快门、模式切换及其他角色动作在用户回合处理。[主动看画面](../modes-and-prompts.md#主动看画面)

解析器默认严格模式，普通客户端使用 `allow_plain_speech=True` 将标签外文字增量适配为 speak，记录 `parser.plain_text_adapted`。模型混用两种闭合写法时（例如 `<speak:好了。</speak>`），同一适配器只显示“好了。”。自然语言不会被推断为动作或模式。判断原生标签质量必须检查原始输出。

指导模板不提供角色动作，但客户端没有按模式禁止合法动作；指导期间意外生成的动作仍会改变隐藏的角色状态。模板约束和运行权限是两个不同层次，不能声称已经硬性隔离。

## 切换与旧入口

mode 标签先记录 `session.mode_requested`。新本地会话就绪后记录 `session.mode_ready` 并更新画面。切换保留摄像头连接，每次进入内置合照都使用本库的入场姿势，并根据当前画面重新定位。自定义 prompt 使用自己的模板。

`<photo:enter>` 只保留历史解析兼容；分发时记录 `command.skipped`，原因 `legacy_photo_entry_use_mode_tag`，不入画、不切换。基于旧版 `move` 或独立 `scale` 动作的自定义模板及调用方应改发一条含绝对落点的 `teleport`。
